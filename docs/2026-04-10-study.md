## 1. 사진 업로드 기능

### 무엇을?
사입 등록 모달에서 상품 사진을 찍거나 라이브러리에서 선택해서 저장

### 어떻게?
- `<input type="file" accept="image/*">` — iOS/안드로이드 모두 카메라 + 라이브러리 지원
- 선택한 파일 → `FileReader`로 미리보기 생성
- **Supabase Storage** `item-photos` 버킷에 업로드 → 공개 URL 저장
- DB `items` 테이블에 `photo_url` 컬럼 추가 필요

```js
// 파일 선택 → 미리보기
const reader = new FileReader();
reader.onload = (ev) => setPhotoPreview(ev.target.result);
reader.readAsDataURL(file);

// Supabase Storage 업로드
await supabase.storage.from("item-photos").upload(path, photoFile);
const { data } = supabase.storage.from("item-photos").getPublicUrl(path);
```

### 배운 점
- `useRef`로 숨긴 input을 버튼 클릭으로 트리거할 수 있다
- Supabase Storage 버킷은 **Public**으로 설정해야 URL로 이미지 접근 가능

## 2. 월별 필터 칩

### 무엇을?
재고/판매/거래내역 화면에서 월을 탭하면 그 달 데이터만 보이게

### 어떻게?
```js
// 데이터에서 존재하는 월만 추출
const availableMonths = useMemo(() => {
  const months = [...new Set(items.map(i => i.purchase_date?.slice(0, 7)).filter(Boolean))];
  return months.sort((a, b) => b.localeCompare(a));
}, [items]);

// 필터 적용
const matchMonth = selectedMonth === "전체" || i.purchase_date?.startsWith(selectedMonth);
```

### 배운 점
- `Set`으로 중복 제거 후 배열로 변환: `[...new Set(arr)]`
- `startsWith("2026-04")`로 날짜 월 필터링
- `useMemo`로 불필요한 재계산 방지

## 3. 월별 리포트 상세 모달

### 무엇을?
거래내역의 월별 리포트 행을 탭하면 그 달의 사입/판매 목록 + 비용 상세가 뜨는 모달

### 핵심 문제 & 해결
처음엔 날짜로 재필터링했더니 판매 목록이 안 나왔음.
→ **`monthlyReport` 계산할 때 아이템 배열을 직접 담아서** 모달이 그대로 사용하도록 수정

```js
// monthlyReport useMemo에 배열 포함
map[buyKey].purchasedItems.push(i);
map[sellKey].soldItems.push(i);
map[sellKey].shippingCost += i.shipping_cost || 0;
```

### 비용 분리 표시
- 사입비용 / 배송비 / 매출 → 순이익 순서로 구분

### 배운 점
- 집계 데이터를 만들 때 raw 아이템도 같이 저장해두면 나중에 재필터링 불필요
- 모달에서 `items-end` + `rounded-t-[20px]`으로 모바일 바텀시트 스타일 구현

## 4. 설정 — 기타 비용/수입 조정

### 무엇을?
배송비, 수수료 등 개별 상품과 무관한 지출/수입을 수동으로 추가/삭제

### 어떻게?
- `localStorage`에 저장 → 새로고침해도 유지
- `useEffect`로 변경될 때마다 자동 저장

```js
const [extraItems, setExtraItems] = useState(() => {
  try { return JSON.parse(localStorage.getItem("ako_extra_costs") || "[]"); }
  catch { return []; }
});

useEffect(() => {
  localStorage.setItem("ako_extra_costs", JSON.stringify(extraItems));
}, [extraItems]);
```

### 배운 점
- `useState` 초기값에 함수를 넘기면 한 번만 실행됨 (lazy initialization)
- `localStorage`는 문자열만 저장 → `JSON.stringify/parse` 필수

## 5. Netlify 배포

### 필요한 것
1. `netlify.toml` 파일 — 빌드 설정
2. 환경변수 — Supabase 키

```toml
[build]
  command = "npm run build"
  publish = "dist"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

### `[[redirects]]` 왜 필요해?
React는 SPA(Single Page App). 새로고침하면 Netlify가 `/재고` 같은 경로를 실제 파일로 찾다가 404 에러남.
→ 모든 경로를 `index.html`로 보내서 React가 처리하게 해야 함

## 6. Supabase 연동 트러블슈팅

### 문제들과 해결

| 오류 | 원인 | 해결 |
|---|---|---|
| `Invalid supabaseUrl` | 환경변수 미설정 or 잘못된 값 | URL이 `http`로 시작하는지 검사 후 폴백 |
| 데이터 안 보임 | RLS 활성화 + 정책 없음 | RLS 비활성화 or SELECT 정책 추가 |
| `Forbidden use of secret API key` | service_role 키를 브라우저에서 사용 | anon(publishable) 키로 교체 |

### Supabase 키 종류
- **anon key** (publishable): 브라우저에서 써도 됨 ✅
- **service_role key** (secret): 서버에서만! 브라우저 절대 금지 ❌

### Netlify 환경변수
Vite 앱은 환경변수 이름 앞에 **`VITE_`** 붙여야 클라이언트에서 읽힘
```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_...
```

### Windows .gitignore 주의
`.gitignore`에 `Lib/` 쓰면 Windows에서 `lib/`도 무시됨 (대소문자 구분 없음)
→ `!lib/` 추가로 예외 처리

## 오늘 배운 핵심 개념 요약

| 개념 | 설명 |
|---|---|
| `useMemo` | 값이 바뀔 때만 재계산. 성능 최적화 |
| `useRef` | DOM 요소 직접 접근 (input 클릭 트리거 등) |
| `FileReader` | 브라우저에서 파일을 읽어 미리보기 생성 |
| Supabase Storage | 이미지 등 파일 저장소. Public 버킷 = URL 공개 접근 |
| localStorage | 브라우저에 데이터 영구 저장 (서버 없이) |
| RLS | DB 행 단위 접근 제어. 정책 없으면 아무도 못 읽음 |
| SPA 리다이렉트 | 모든 경로 → index.html로 보내야 React 라우팅 작동 |
